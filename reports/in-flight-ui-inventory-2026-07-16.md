# In-Flight UI Inventory (Nuclear Option, flat game)
See final agent summary; full evidence in .decomp-tmp/
Date 2026-07-16. Evidence: ilspycmd 8.2 decompile of Assembly-CSharp.dll; class sources cached in .decomp-tmp/ (68 files).

## 0 Render architecture
Two cameras: CameraStateManager.mainCamera + cockpitCamRender (cockpit mesh, enabled in CameraCockpitState.EnterState, near 0.2). ALL 2D UI is screen-space uGUI positioned via WorldToScreenPoint, z flattened: always on top, zero 3D occlusion. World-space exceptions: TacScreen (RenderTexture+screenMaterial, night dimming), TargetScreenUI/LandingScreenUI (displayCanvas.worldCamera=UICam, under TacScreen.targetCamDisplay/landingCamDisplay), CockpitWarningLights (Renderer[] lightRenderers). FlightHud.EnableCanvas toggled by pause (GameplayUI.PauseGame), map-maximize (DynamicMap.Maximize), cockpit state. DynamicMap.EnableCanvas only when aircraft alive + CameraMode.cockpit. Hit markers cockpit-state only. Camera states: cockpit/orbit/free/TV/selection/relative/encyclopedia/chase/controlled; full HUD only in cockpit.

## 6 Render-space / occlusion summary
Screen-space overlay, always on top (no depth occlusion): FlightHud canvas (boresight, ladder, compass, VV, waterline, weapon states, gauges, HMD), CombatHUD layer (markers, threats, weapon status, CM, hit markers, target arrow/info, notch), Objective+Airbase overlays, DynamicMap min+max, VirtualMFD, tooltips, all GameplayUI (hurt, messages, killfeed, chat, leaderboard, dialogue, menus, radial). World-space, occluded normally: TacScreen + Target/Landing cam pages (RenderTexture on cockpit screens), CockpitWarningLights (3D lamps). HUD-on-HUD: no depth, only canvas sort + manual de-clutter (HMD hide-distance, marker minimize, TextNoOverlap, alpha fades near boresight).
